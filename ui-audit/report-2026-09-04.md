## HIGH — visible correctness defects

### H1. UV gauge gradient: the green half is invisible
`Modules.kt:193-208` (UvGauge). The arc is drawn from 180° to 360° (the top
semicircle), but `Brush.sweepGradient` distributes its 5 color stops over the
full 360° starting at 3 o'clock. The visible sector therefore only shows
gradient fractions 0.5→1.0 — **yellow → orange → red**. The green and
yellow-green stops (low UV) land on the undrawn bottom half.

Evidence: `screenshots/audit_12_scrolled_2.png` — arc reads yellow→red, no green,
while the marker for a moderate value sits on yellow.

Fix: give the sweep gradient explicit stops pinned to the visible sector, e.g.
`listOf(0.5f to green, 0.75f to yellow, 1f to red)` (same `center`), or rotate
the gradient so 0° aligns with the arc's start.

### H2. Pressure gauge: same defect + always-violet marker
`Modules.kt:516-530` (PressureGauge). Identical sweep-gradient misalignment:
visible arc = fractions 0.5→1.0 → **teal → amber**; the violet "low pressure"
stops are on the hidden bottom half. Screenshot confirms: teal→amber, no violet.

Additionally `Modules.kt:536` draws the marker in hardcoded
`CirrusPalette.Violet` regardless of the pressure value — unlike UvGauge, which
colors its marker by category (`CirrusPalette.uvColor(uv)`). The marker color
should map the pressure (e.g. violet low → amber high) to match the arc.

### H3. Hardcoded English strings bypassing strings.xml
User-visible:
- `"…° vs actual"` — FeelsDelta pill, `Modules.kt:347`
- `"Until $endText"` — expanded alert end time, `AlertBanner.kt:112`

TalkBack-only:
- `"$category UV index"` — `Modules.kt:169`

Not resources, so they can't be translated or tuned with the rest of the copy,
and they silently diverge from strings.xml conventions. Related: the error copy
in `WeatherViewModel.kt:93,96` duplicates `R.string.error_offline` /
`error_generic` as hardcoded literals (and appends the raw exception message to
the generic one). ViewModels can't call `stringResource` — pass resource IDs and
resolve in the UI.

### H4. Only the first weather alert is rendered
`WeatherScreen.kt:320-330` — `bundle.alerts.first()` only. With two active
alerts (common in storm season) the second is silently invisible; there is no
"1 of 3" affordance. Either stack the banners or add a pager/count.

## MEDIUM — inconsistencies users notice

### M1. Three different clock policies on one screen
- Hourly strip columns: 12-hour `"h a"` → "6 PM" (`TimeFormats.kt:12`)
- Sun times, footer "Updated", alert end: 24-hour `"HH:mm"` → "18:32"
- Settings delivery-time picker + row: follows the **system** 12/24h setting
  (`SettingsScreen.kt:477,502`)

On a 12-hour device, sunset reads "18:32" while the settings picker shows
"6:30 AM". On a 24-hour device the hourly strip still says "6 PM". Pick one
policy (recommend: follow the system setting everywhere via a
`TimeFormats.clockOf(system24)`).

### M2. "Today" is computed two different ways
DailyForecast labels Today/Tomorrow by **epoch day vs the clock in the city's
zone** (correct). But the hero H:/L: (`HeroHeader.kt:37`), the sunset marker
(`WeatherScreen.kt:249`), and Sun/Moon modules (`WeatherScreen.kt:447`) all use
positional `days.firstOrNull()`. If the backend's first day ever disagrees with
local today (late-evening fetch, cache lag), the hero shows another day's H/L
while the daily card labels a different row "Today". Add one helper
(`days.firstOrNull { it.dateEpochDay == todayEpoch }`) and use it everywhere.

### M3. `now` frozen at composition
`WeatherScreen.kt:243` — `remember(bundle.fetchedAt) { Instant.now() }`. Drift
is bounded by the 10-minute auto-refresh, but a screen left open across local
midnight keeps yesterday's "Today" row and a sun-arc dot that lags. A
clock-tick state (or keying on the local date) would close it.

### M4. Alert banner accessibility
`AlertBanner.kt` — the clickable has no `Role.Button`, no expanded/collapsed
`stateDescription`, and the ⚠️ emoji + headline + snippet are not merged into a
single TalkBack node. Also the collapsed 2-line snippet uses default clip, not
`TextOverflow.Ellipsis`, so it hard-cuts mid-glyph. The daily rows already do
all of this correctly — copy that pattern.

### M5. "Now" column is index-based, not clock-based
`HourlyForecast.kt:358-360` — `isNow = index == 0`. Verified the backend
currently returns the current hour first, so this is latent; but with a stale
bundle the first column can be an hour+ old while still saying "Now". Tie it to
the actual clock (like the daily card's todayEpoch) and let real hours render
their time label when they're no longer "now".

### M6. Font-scale degradation is accepted in hourly, untested in daily
The hourly strip deliberately trades scale for curve geometry — at 2x, hour
labels ellipsize ("7 P…" — visible in `fixes/fix_20_fontscale2_hourly.png`),
which is a documented tradeoff. The daily rows have the same exposure (fixed
46dp row, 84dp label, 40dp temp columns) and were not part of that earlier
audit; "100%" precip at 2x in a 46dp column will clip. Decide: accept + note,
or scale key column widths with `LocalDensity.fontScale` beyond ~1.3.

## What's genuinely good (keep it this way)

- Honest empty states (a quiet line, never a vanishing card or a dead chevron).
- Stale-data banner + keep-last-good-bundle instead of silent failure.
- Retry affordances everywhere: refresh pill, pull-to-refresh, per-city mini
  retry, search-failed tap-to-retry.
- TalkBack discipline in the forecast cards: one merged stop per hour column,
  announced expand/collapse state, announced selection in the language picker.
- Entrance choreography keyed per city with `rememberSaveable` (no replay on
  scroll-back, replay on city swap); reduce-motion honored; particles capped at
  ~32fps.
- Consistent glass-card language (24dp radius, hairline border) and
  `IntrinsicSize.Min` so module footers share a baseline.
- Destructive delete always confirms; IconButtons kept at 48dp targets.
- Status-bar icon luminance adapts to the weather gradient.
