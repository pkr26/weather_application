# Cirrus — Re-Audit of the Fix Commit (2026-09-04, commit `2671665`)

Method: six independent audits (backend security, backend correctness/resilience, Android
data/notify, Android UI/Compose, test quality, infra/CI/docs) + live empirical verification on
this machine: backend typecheck + full suite run, live server boot (auth gate, health, SIGTERM
drain, log-redaction capture), `npm audit`, `:core:test`, and `:app:compileDebugKotlin` with the
complete error list captured. Every P0 below was verified by execution or personal code read,
not agent hearsay. All findings cite file:line.

---

## Verdict — no BS

**The fix commit was never built, never tested, and never CI'd — and its own test suite proves
two of its headline claims false.** The genuinely hard things that were finished (security core,
particles, DST math, atomic registration, log redaction) are real and survived adversarial
probing. But the commit as it stands is a partially-applied refactor:

1. **The Android app does not compile** — ~80 Kotlin errors across 14 files, including the data
   layer (`WeatherRepository`, `LastKnownWeatherStore`, `Workers` reference a
   `BundleResponse`/`BriefingResponse` that a half-finished DTO refactor left in the wrong
   package), outright syntax errors in `AlertBanner.kt`, missing `setValue`/haptics/`items`
   imports, an easing function (`easeInOutSine`) that doesn't exist in the pinned Compose
   version, and `minimumInteractiveComponentSize` imported from the wrong package in 3 files.
   Build-artifact timestamps confirm the committed sources postdate the last successful build.
2. **The backend suite is red: 23 of 386 tests fail** on the committed tree (16 in
   `errors.test.ts` — mocks lack `setHeader` after `errors.ts:50` added it; 6 in `api.test.ts`;
   1 in `cache.test.ts`). Two of those failures are **real product bugs**, not stale tests (P0-3,
   P0-4 below). The commit was made with a red suite while TESTING.md says "all green".
3. **CI has never run anywhere** — the repo has one commit and **no git remote**. The
   "hardened CI / R8 release smoke build" claims are unexecuted aspiration, and the android job
   has a permissions conflict that would fail it anyway (`ci.yml:57` dependency-graph submission
   vs `contents: read`).
4. **Docs numbers are false or self-contradicting**: three different test counts (275/292/292)
   vs 386 actual; README says Stryker "86%, breaks below 75%" ten lines away from "98% gate";
   PIT "83%/80%" vs configured 98/98; both checked-in mutation reports **predate the committed
   code** (the entire new resilience layer — http.ts, readiness.ts, compression.ts — has never
   been mutation-tested).
5. **One flagship Android fix is inverted** (the off-screen polling pause kills foreground
   auto-refresh entirely) and **one is self-corrupting** (the offline catch-up duplicates the
   WorkManager chain → two briefings every morning until the app is reopened).

## P0 — fix before anything else

1. **App module does not compile.** Empirically verified: `:app:compileDebugKotlin` fails with
   ~80 errors / 14 files. Representative causes:
   - `data/remote/dto` refactor incomplete: `BundleResponse` defined in
     `CirrusApi.kt:90` (`data.remote`) but imported from `data.remote.dto` in
     `WeatherRepository.kt:5` and `LastKnownWeatherStore.kt:4` — the offline-weather feature,
     repository, and workers don't resolve.
   - `AlertBanner.kt:79` syntax mangle: `.clickable(role = Role.Button) { {` — nested lambda
     plus brace errors cascading to `:149-150`; even after fixing braces the tap-handler body is
     a never-invoked lambda (see P0-6).
   - `Clock.kt:20`, `Motion.kt:26`: `by`-delegate assignment without
     `import androidx.compose.runtime.setValue`.
   - `SettingsScreen.kt`: missing `imePadding` (:337), `SnackbarDuration` (:137),
     `SnackbarResult` (:139), `androidx.compose.foundation.lazy.items` (:466 — the language
     picker).
   - `HourlyForecast.kt:202-204`: `ScrollState`/`canScrollForward`/`canScrollBackward` without
     imports (also makes the saveable scroll state dead).
   - `HapticFeedbackType` unresolved in 5 files; `BrandedLoading.kt:5,43` uses
     `easeInOutSine` (not in pinned Compose); `WeatherScreen.kt`/`CityListScreen.kt` import
     `minimumInteractiveComponentSize` from `foundation.layout` (it's in `material3`);
     `GlassCard.kt:54` `shape`; `Workers.kt` `BriefingResponse`/`title`/`body`;
     `CityListViewModel.kt:143` arg mismatch.
   **Fix:** complete the refactor, add the imports, and **build before committing**.

2. **Backend suite red at HEAD: 23/386.** Root causes: `tests/errors.test.ts` `fakeRes` lacks
   `setHeader` (17 failures) after `errors.ts:50` added `Cache-Control: no-store`;
   `cache.test.ts:163` exact-match not updated for new `ttlMs` meta; the remaining 6 are the
   two product bugs below plus the ttlFor-override divergence. Stryker cannot run at all on a
   red suite. **Fix:** update the doubles, fix P0-3/P0-4, re-run everything, regenerate every
   documented number from that run.

3. **The "degraded bundles cache briefly (30 s)" fix does not exist.**
   `routes.ts:77` `cacheable: (b) => !b.degraded` + `cache.ts:80-82` (uncacheable ⇒ never
   `set()`) means degraded bundles are **never stored**; the `ttlFor` degraded arm
   (`routes.ts:78`) is unreachable dead code and `DEGRADED_CACHE_TTL_MS` is dead config. The
   comment above it (`routes.ts:70-74`) and the CHANGELOG claim the opposite behavior. The
   commit's own tests (`api.test.ts:233-276`, `:386-411`) assert the documented behavior and
   **fail**. The prior audit's P0-4 (quota ∝ requests under persistent soft failure) persists,
   mitigated only by the circuit breaker after 5 consecutive failures.
   **Fix:** `cacheable: () => true` (or drop it) and keep `ttlFor`. The failing tests then pin it.

4. **gzip middleware strips `Content-Type` from every compressed response.**
   `compression.ts:26-39` — the compressed branch calls `res.end(gz)` directly, bypassing
   Express's Content-Type set. Live-verified: `/api/v1/languages` (compressed) returns no
   Content-Type. Affects every >1 KB response — the primary API surface. Also: `Accept-Encoding:
   gzip;q=0` still gets gzip (q-values ignored, probe-verified), `Vary` set only on the
   compressed path. The single gzip test fails for a second reason (fixture < 1 KB threshold).
   **Fix:** set `Content-Type: application/json; charset=utf-8` on the gzip path, parse
   q-values, set `Vary: Accept-Encoding` unconditionally, test with a >1 KB fixture.

5. **"Polling pauses off-screen" is inverted — foreground auto-refresh never runs.**
   `MainActivity.kt:135` — `setScreenVisible(event == Lifecycle.Event.ON_START)` fires for every
   lifecycle event; ON_RESUME (which always follows ON_START, and is replayed on observer
   registration) evaluates false. `screenVisible` is false while foregrounded; the 10-minute
   loop (`WeatherViewModel.kt:111-116`) checks it at tick time → never refreshes. The fix is
   worse than the original bug (too-much polling became zero polling).
   **Fix:** `setScreenVisible(lifecycle.currentState.isAtLeast(STARTED))`.

6. **Severe-weather alert expansion is dead code.** `AlertBanner.kt:79-82` — the click handler
   body is a nested, never-invoked lambda (`{ {`); haptic + `expandedFor` never execute. Even
   after the file compiles, users can never expand an alert to read the description.
   **Fix:** remove the inner braces; restore a real click handler.

7. **The offline catch-up corrupts the briefing chain → recurring double briefings.**
   On final failure `Workers.kt:140-145` enqueues the catch-up **and** appends tomorrow's
   worker; the catch-up's success path (`Workers.kt:117-124`) appends again under
   `ExistingWorkPolicy.APPEND` (`NotificationScheduler.kt:66-67`) → chain of length 2 persists
   indefinitely: two briefings every morning (double heads-up + double upstream fetch) until
   the next app open REPLACEs it. **Fix:** the catch-up must not APPEND (skip rescheduling, or
   REPLACE).

## P1 — high impact

### Backend
- **Briefing ignores `degraded`** — `generator.ts:137-254` never reads the flag; a degraded
  (empty-hours) morning briefing confidently says "No rain expected today". This is the exact
  harm of the prior audit's P0-3, persisting in the flagship path (`routes.ts:227` computes
  degraded into the bundle; the generator throws it away; `briefing.test.ts:250-261` even pins
  it). Omit the precip line when degraded/empty; surface `degraded` on the result.
- **Single-flight waiters get wrong TTL metadata** — `cache.ts:66-72` returns constructor TTL
  for coalesced waiters: a degraded leader (30 s) + waiter advertising `max-age=600` with
  `degraded: true` — OkHttp's new disk cache may pin degraded payloads 10 min. Stash the
  computed TTL with the in-flight result.
- **`ttlFor` overrides injected cache TTL on misses** — `cache.ts:90`: header TTL comes from
  config regardless of the cache instance's own TTL (failing aged-TTL test pins the old,
  correct contract). In production wiring they coincide; in tests and any future cache with a
  different TTL, headers lie.
- **Retry-After is nominal** — `http.ts:36-41` parses integer seconds only (HTTP-date → NaN →
  0); a 429's Retry-After is parsed then discarded (429 is non-retryable, `:73-77`); upstream
  Retry-After never forwarded to clients; cap silently clamps 120 s → 5 s. Zero tests.
- **CI android job will fail on first push** — `ci.yml:16-17` `contents: read` vs `:57`
  `dependency-graph: generate-and-submit` (needs `contents: write`). Job-scope the permission
  or use `generate`.
- **Release workflow has three independent runtime breakages** — silent debug-signed AAB
  fallback when keystore secrets absent (`release.yml:29` + `app/build.gradle.kts:87-91`);
  `VERSION_CODE=$(git rev-list --count HEAD)` = **1** < shipped versionCode 3 (`release.yml:39`);
  Docker push gated on `vars.DOCKER_REGISTRY` with **no registry login step** (`release.yml:68-75`).
- **Dockerfile: `/app/data` never created/chowned** — `VOLUME` materializes root-owned; the
  non-root `app` user gets EACCES on first device registration (500s) while `/health` stays
  green. `RUN mkdir -p /app/data && chown app:app /app/data`.
- **Device store wipes the registry on transient I/O errors** — `deviceStore.ts:108-113`: any
  non-ENOENT read error (EACCES/EMFILE) logs "starting fresh" and the next persist overwrites
  `devices.json` from the empty state — every device secret destroyed. Fail 503 and retry
  instead of marking `loaded`.
- **Circuit breaker keyed by path only** — `googleWeather.ts:60`: one language's bad
  `languageCode` (4xx ×5) opens the alerts breaker for **all** languages for 30 s. Key by
  `path|languageCode` or stop counting 4xx.
- **A lingering `nextPageToken` on the final page marks healthy bundles truncated** —
  `googleWeather.ts:165-168` sets `truncated` even when `merged.length >= target`; combined
  with an upstream contract change this would flag every bundle degraded forever.
  `truncated = token !== undefined && merged.length < target`.
- **Upstream contract changes served as healthy** — a renamed list key (empty page) passes with
  `degraded=false` and is cached at full TTL (`googleWeather.ts:162,173-176`); "empty" is never
  treated as an error.
- **targetSdk/compileSdk 35** — still a 2026 Play blocker (carried from prior audit, unclaimed).

### Android (beyond the P0s)
- **`rememberSaveable` holds a non-storable `SavedCity`** — `CityListScreen.kt:91`: neither
  Parcelable nor java.io.Serializable → save-time crash / dropped state with the delete dialog
  open during a config change. Save `city.id` and re-resolve.
- **Single-hour forecast crashes the spline** — `HourlyForecast.kt:407-416` builds `Spline`
  inside `drawWithCache` for `n ≥ 1` while `Spline.kt:16` requires ≥ 2 points; the guard at
  `:449` runs after the cache block threw. Truncated backend data (prior P0-3 made those
  possible) or unparseable times (`Mappers.kt:89-90` drops them) → crash.
- **Offline city switch shows the previous city's weather under the new city's name** —
  `WeatherViewModel.kt:90-103,176-178`: switching A→B while Ready skips hydration; failed
  refresh keeps A's bundle with B's name and a "last forecast" banner that lies. The
  LastKnownWeatherStore is bypassed exactly when it was built for this case.
- **Boot-time REPLACE kills today's pending briefing** — `CirrusApp.kt:26-31` reschedules on
  every process start: opening the app offline at 09:00 cancels the pending (CONNECTED-starved)
  08:00 worker and schedules tomorrow. Persist last-posted date; catch up instead.
- **Null-headline alerts permanently occupy the flood cap** — `Workers.kt:73-95`: `take(4)`
  before the null check; null-headline alerts never get marked seen, re-occupy slots forever,
  and can starve postable alerts. Use the `alertType` fallback the UI mapper already has.
- **Test notification reports success when posting failed** — `SettingsViewModel.kt:147-152`
  ignores `Notifier.showBriefing`'s Boolean → false "sent" snackbar when permission revoked.
- **Keystore vault failure is unrecoverable and silent** — `SecretVault.kt:29-40` creation
  throw propagates into `DeviceRegistrar.kt:75-77`'s blanket catch → registration dead forever
  with no reset (401-recovery never triggers because no call is ever made). Catch → clear →
  return null to force clean re-registration.
- **Cache identity is id-only for the device city** — hydration keys on `"device"` while
  coordinates move: offline launch after relocating shows the old location's numbers under
  "My Location". Include rounded coords in the key or skip hydration on coordinate mismatch.
- **Notifications fire for a default city the user never chose** — `Workers.kt:16-22` falls
  back to `defaultCities().first()` (Hyderabad) when the user has zero cities.
- **Timezone change while dead → one wrong-time briefing** — delay computed at schedule time
  against `ZoneId.systemDefault()` (`NotificationScheduler.kt:59-60`); self-heals on next
  reschedule. (DST itself is correctly handled and genuinely tested.)

## Order of attack

1. **Make it build** (P0-1): finish the DTO refactor, add ~10 imports, fix the AlertBanner
   braces, replace `easeInOutSine`, then `assembleDebug` + `testDebugUnitTest` until green.
2. **Make the suite honest** (P0-2/P0-3/P0-4): fix `cacheable`/`ttlFor`, set Content-Type on the
   gzip path, update `fakeRes`/stale assertions — five of the six api failures flip green the
   moment the two one-line product fixes land.
3. **Land the two inverted UX fixes** (P0-5, P0-7) + the alert-tap handler (P0-6) with tests.
4. **Regenerate every documented number from one verified run** (vitest, stryker, pitest), add
   the remote, and let the first real CI run — after fixing the `ci.yml` permission conflict —
   become the source of truth. Until then, treat every quality number in the docs as fiction.
5. Then the P1 list (briefing degraded handling, release workflow, Dockerfile data dir, device
   store I/O-error wipe, splash/saveable crash, single-hour spline, offline city switch).

**The theme this time:** the hard engineering is largely done and holds under fire — the
process around it collapsed. Nothing was built, nothing was run, nothing was pushed, and the
docs describe a repository that does not exist.
