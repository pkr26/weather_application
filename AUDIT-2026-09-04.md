# Cirrus — Full Codebase Audit (2026-09-04)

Scope: entire repo — `backend/src` (Node/TS), `app` + `core` (Android/Kotlin), build/CI/docs.
Method: four parallel deep audits (backend, Android data/notify, Android UI, build/CI), plus
independent verification of the highest-impact claims (particles bug, log redaction gap, mutation
report numbers, git status, env hygiene). All findings cite file:line.

---

## Verdict

The code quality is genuinely top-tier — better than most shipped production apps. But there are
**7 real P0 defects** (two silently break flagship features), and the gap to "best app ever" is
**structural**: no version control, no release pipeline, no offline story, no widgets, no
instrumented tests, no observability. Fixing the P0s protects what exists; the structural work is
what makes it best-in-class.

## P0 — Real bugs, fix first

1. **Rain & snow FX render one frozen frame** (verified by code read).
   `app/.../ui/fx/Particles.kt:94-108` (Rain), `:143-153` (Snow): draw lambdas never read the
   tick state (`frame`/`time` are written by `FrameLoop` but only the coroutine reads them), so
   Compose never invalidates the canvas — every rainy/snowy forecast draws one static frame while
   the loop integrates up to 140 particles at ~32 Hz for nothing. Stars/lightning animate because
   they read state inside draw (`:181`, `:212`). A screenshot-based audit could never catch this.
   **Fix:** read the tick inside each draw lambda (one line per effect).

2. **The shared API token is written to every access log** (verified).
   `backend/src/app.ts:71-74`, `backend/src/logger.ts:8-13`: redact lists cover `authorization`,
   `x-goog-api-key`, `x-device-secret` — but not `x-api-token` (`backend/src/security/apiToken.ts:12`).
   With `API_TOKEN` set, every request's log line carries the master credential in plaintext.
   **Fix:** add `'req.headers["x-api-token"]'` to both lists + a log-content test.

3. **Truncated forecasts are cached as healthy.**
   `backend/src/upstream/googleWeather.ts:134-139`: a page-2 failure after page-1 success is
   swallowed and the partial list returned without `degraded`; `bundleIsCacheable`
   (`backend/src/routes.ts:59`) then caches it for the full 10 min. A single 5xx can freeze a
   24-of-72-hour forecast — and briefings derived from it can say "no rain" during an afternoon
   storm. **Fix:** propagate truncation from `callPaged`, set `degraded`, add test
   (page-2 fail → degraded → cache miss).

4. **A persistent soft upstream failure disables caching entirely — quota-burn amplifier.**
   `googleWeather.ts:212-229` + `routes.ts:59` + `cache.ts:60-67`: a permanent soft failure
   (alerts 403, bad languageCode 400) makes every request re-fire all 5 upstream calls, forever.
   One misconfiguration converts "quota ∝ users" into "quota ∝ requests" and can starve the
   critical current-conditions path. **Fix:** short-TTL cache for degraded bundles (30–60 s),
   never-cache only on network/5xx; add a per-endpoint consecutive-failure breaker.

5. **Notification workers have no network Constraints; the briefing gives up for the day when offline.**
   `app/.../notify/NotificationScheduler.kt:40-46,66-71` (no `Constraints` anywhere), `Workers.kt:64-74`
   (after 3 retries: schedule tomorrow, `success()`). Offline at 08:00 → briefing silently skipped.
   Also: the "fires without drift" doc claim is wrong for Doze (WorkManager is inexact; no exact-alarm
   permission is declared). **Fix:** `setRequiredNetworkType(CONNECTED)` on both requests; on final
   failure enqueue a connectivity-triggered one-shot; consider `setExactAndAllowWhileIdle` for the
   briefing trigger.

6. **The project is not a git repository** (verified). `.github/workflows/ci.yml`, both `.gitignore`s
   and the README's "CI runs all of the above on every push" are aspirational — nothing can run.
   No history, no rollback, no bisect, no provenance. **Fix:** fix `.gitignore` gaps first (below),
   then `git init`, push, and prove CI goes green once.

7. **Release builds are unsigned and targetSdk 35 is a 2026 Play blocker.**
   `app/build.gradle.kts:56-63` (no signingConfig, no `isShrinkResources`), `:40,45`
   (compileSdk/targetSdk 35; Play's annual deadline requires 36 in 2026, needs AGP 8.9+).
   **Fix:** signing config from env vars, `bundleRelease` in a release workflow, bump SDK/AGP,
   opt into Android 16 behaviors (predictive back, edge-to-edge).

## P1 — High impact

### Backend
- **TOCTOU on first device registration** — `routes.ts:242-267` + `deviceStore.ts:144-155`:
  concurrent first POSTs return two different 201 secrets; an attacker racing a victim's *first*
  registration can seize the record. Add atomic `createIfAbsent` + concurrency test.
- **Retries have zero backoff** — `googleWeather.ts:89-91`: transient 5xx → up to 15
  simultaneous upstream calls per request. Add exponential backoff + jitter, honor `Retry-After`;
  `GeocodingClient` has no retry at all (inconsistent).
- **No overall deadline / circuit breaker** — worst case 24 s per request during brownouts
  (per-attempt timeout × attempts, no backstop). Propagate a per-bundle deadline; add a breaker.
- **Graceful shutdown never flips readiness** — `index.ts:43-56`: `/health` stays green while
  draining; LBs keep routing to an instance that hard-exits at 10 s. Add draining flag → 503,
  split `/live` vs `/ready`.
- **Location PII in every access log** — pino-http default serializer logs full query strings:
  coordinates, city names, search terms, device IDs. Custom `req` serializer logging path only.
- **No response compression** — bundles >100 KB uncompressed dozens of times/day per user; OkHttp
  sends `Accept-Encoding: gzip`, server never compresses. Add `compression()`. Cheapest win.
- **Cache key multiplies ×27 by language although only alerts vary** — `routes.ts:86-95`:
  core weather is identical across languages (`googleWeather.ts:103-110,158-196` hardcode `en`).
  Split cache: core by coords, alerts by coords+lang.
- **Prototype-pollution defense not on the write path** — `deviceStore.ts:58,146,152`: normal
  prototype object, raw key writes; only the route-layer zod denylist protects today.
  `Object.create(null)` + forbidden-key guard.

### Android (data/notify)
- **No local persistence of last-known weather** — offline cold start is a dead error screen;
  the excellent `stale` machinery only works within one process. Persist last bundle per city,
  hydrate `Ready(bundle, stale = true)` on open.
- **Re-locating never refreshes the screen** — id-only identity (`WeatherViewModel.kt:60-61`,
  `MainActivity.kt:103`): same id + new coordinates = stale location's weather shown silently.
  Key on coordinates too.
- **10-minute auto-refresh polls while backgrounded** — `WeatherViewModel.kt:70-75`: viewModelScope
  survives Home; make the tick lifecycle-aware (STARTED).
- **`AlertWorker` swallows `CancellationException`** — `Workers.kt:115-117` (BriefingWorker does it
  right at `:62-63`).
- **Keystore-encrypted prefs read on the main thread** — `SecretVault.kt:40` via
  `viewModelScope` (Main.immediate): first notification toggle does Keystore + decrypt on main.
  `withContext(Dispatchers.IO)`.
- **Weather data always fetched in English** — `CirrusApi.kt:28`, `WeatherRepository.kt:19`:
  localized notifications but English on-screen condition text. Thread the language through.
- **Sheet/scroll state lost on recreation** — `MainActivity.kt:68-69` plain `remember` for root
  nav flags (dark-mode/font/locale changes recreate); `HourlyForecast.kt:191` scroll state not
  saveable. `rememberSaveable`.
- **Deleting the last city silently no-ops** — `CityListViewModel.kt:169-181` hides a permanent
  splash bug; design a real empty-home state (string already exists: `cities_empty`).
- **Onboarding dialog can flash for returning users** — `MainActivity.kt:133-161` race between
  two collectors; tri-state boot flow.
- **Settings snackbar renders behind the gesture nav bar** — `SettingsScreen.kt:301-310` missing
  `navigationBarsPadding()/imePadding()`.
- **Seen-alert eviction is lexicographic (random)** — `SettingsStore.kt:213-219` evicts by hex
  order while claiming "newest kept": still-active alerts can re-buzz. Persist key→timestamp.

### Build / CI
- **R8/minified release build never exercised in CI** (ci.yml builds debug only; serialization
  keep-rules only fail at runtime); add `assembleRelease` + `isShrinkResources`.
- **No dependency-update automation or Gradle vulnerability scanning** — no dependabot/renovate;
  whole Kotlin graph ~18 months stale (AGP 8.7.3, Kotlin 2.0.21, Compose BOM 2024.12).
- **CI hygiene** — no concurrency group, no permissions block, no timeout, no wrapper validation,
  unpinned action tags, no workflow_dispatch, no Node matrix (engines allows EOL Node 20).
- **No Kotlin static analysis (detekt/ktlint) and zero instrumented tests** — no `androidTest`
  dir exists despite Compose UI + workers being exactly what unit tests can't reach.
- **No release pipeline** — no tag-triggered workflow, no Play upload, no Docker publish, no
  changelog, hardcoded versions (`versionCode 3`, backend `1.0.0`).
- **Docs contradict gates** — README says PIT 83%/gate 80 (actual: 99.2%/gate 98), Stryker 86%/
  gate 75 (actual: 100% of scored, gate 98, 380/1071 mutants ignored), test counts differ across
  three docs (275/265/360 vs ~270 measured). Generate the numbers from CI output.
- **`.gitignore` gaps before first commit** — `backend/coverage/`, `ui-audit/` (12 MB PNGs),
  `.kotlin/`, `.zcode/`, `*.jks`, `.env.*`, `*.apk` would all land in history.

## P2 — Polish (selected; full lists in agent reports)

**Backend:** empty `?lat=` coerces to 0 (serves 0°,0° with 200); device language not validated
against catalog; `'your location'` fallback is English-only in 26 other languages; no
`Cache-Control` on `/languages` or geocode; errors lack `no-store` + `headersSent` guard;
`/health/` exact-string exemption under token gate; FIFO not LRU cache (geocode churn);
no device-secret rotation endpoint; alerts endpoint has no microcache during storms;
`Intl.DateTimeFormat` built per hour in briefing hot path; Dockerfile healthcheck lacks
`--start-period`, base tags not digest-pinned; client disconnects don't abort upstream fetches.

**Android:** alerts marked seen even when posting failed (permission revoked → never re-notified);
DST-blind briefing delay math (`BriefingSchedule.kt:16-20`, no ZonedDateTime); device-zone vs
city-zone ambiguity for the 08:00 briefing; one toggle gates both briefing and severe alerts
(separate channels exist — split the preference); `ACCESS_FINE_LOCATION` declared but never
requested (Play review friction); POST_NOTIFICATIONS permanent-denial dead end (no settings deep
link, test button can silently no-op); geocoding DTOs leak into UI layer; workers hard-cast
`CirrusApp` → untestable (extract use cases); `next hour` precip footer reads `hours[1]`
positionally (stale bundles lie — use ticking now); alert expansion resets on scroll (others use
`rememberSaveable`); status-bar side effect inside `remember` (use DisposableEffect);
12/24h + reduced-motion never re-checked on resume; 44dp/28dp touch targets below 48dp Material
minimum (°C/°F toggle, hero buttons, Try Again); emoji as icons (OEM glyph variance + TalkBack);
no haptics anywhere; no predictive back (`enableOnBackInvokedCallback` missing); no platform
splash screen API; notification tap has no deep link; tweens everywhere, springs nowhere; city
switch discards good content to full loading screen; spline path + gradient stops allocated per
draw frame (`HourlyForecast.kt:386-480`, `DailyForecast.kt:289-417`) — `drawWithCache`;
typography tokens defined but bypassed everywhere; duplicated gradient literals.

**Infra:** Gradle 8.11.1 without `distributionSha256Sum`; `security-crypto` alpha in production
(deprecated upstream — plan migration); no configuration-cache; no OpenAPI spec/API diff; no
ADRs/deploy guide/runbook; no LICENSE (legally "all rights reserved"), CONTRIBUTING, CHANGELOG,
CODEOWNERS; SECURITY.md has duplicated control number 15 and no contact address;
`.env.example` missing `REVERSE_GEOCODING_API_BASE` (undocumented third-party upstream);
`local.properties` still carries the now-unused `WEATHER_API_KEY` from the pre-backend era;
express 4 / zod 3 aging (not vulnerable, just old).

## Test blind spots

Backend: concurrent first-registration race; truncation × degraded × cache interplay; persistent
soft-failure caching behavior; **log content** (no test asserts what is written); empty-string
coords; `index.ts` entirely untested (SIGTERM drain, EADDRINUSE) — excluded from coverage;
error-path cache headers; retry spacing.
Android: worker logic (blocked by the `CirrusApp` cast, no Robolectric); `SettingsStore` trim
semantics (the eviction bug lives exactly there); `Mappers.kt` (zero tests); repository timezone
fallback; `CityListViewModel` (no test file); DST scheduling cases; no instrumented tests at all.

## What's already exceptional — keep it

- **Timing-safe, oracle-free auth** (`deviceAuth.ts:38-75`, `apiToken.ts`): dummy-hash compares,
  no device-existence oracle — better than most production APIs.
- **HTTP freshness engineering** (`routes.ts:43-56`): remaining-TTL on aged hits (not refreshed),
  `X-Cache` transparency, alerts always `no-store` — pinned by real-time tests.
- **Prototype-pollution defense in depth**, adversarially tested at the text level.
- **Atomic self-healing persistence** (`deviceStore.ts:113-142`): tmp+fsync+rename, 0600, write
  queue, corruption recovery, age-prune — textbook for a dependency-free store.
- **Single-flight stampede-safe cache** with pluggable cacheability.
- **Test culture**: per-file 98% coverage gates (not aggregate), PIT 99.2% on :core with written
  mutator rationale, Stryker gate 98 with documented equivalent-mutant ignores.
- **Android device-secret lifecycle**: keystore vault, legacy-key migration with scrubbing,
  mutex-guarded id minting, 401-driven reset — the best-tested area of the app.
- **`WeatherViewModel` state modeling**: stale-flag keep-last-good-bundle, single-flight refresh,
  spinner ownership discipline, CancellationException rigor.
- **`playOnce` entrance system** and clock-correctness discipline (ticking `now`/epoch-day chain).
- **Release-URL guardrail** (release builds refuse the emulator URL) and layered network
  security configs; `allowBackup=false`.
- **Version-catalog discipline**, `FAIL_ON_PROJECT_REPOS`, content-filtered repos.
- **Dockerfile**: multi-stage, `npm ci --ignore-scripts` with supply-chain rationale, non-root,
  real HEALTHCHECK.

## Recommended order of attack

**Week 1 — stop the bleeding (P0s):** particles one-liners; token redaction + log test;
degraded-cache semantics (P0-2/3); worker Constraints + retry-forever-until-connect; git init
(after .gitignore fixes) and prove CI green.

**Weeks 2–4 — protect the core (P1s):** offline bundle cache + re-locate refresh +
lifecycle-aware polling; backend backoff/deadline/breaker + readiness + PII serializer +
compression + cache-key split; signing config + SDK 36 + release-in-CI; rememberSaveable batch.

**Months 2–3 — best-in-class (structural):** baseline profiles + macrobenchmarks; instrumented
test lane; Glance home-screen widget + notification deep links + predictive back + splash API +
haptics + springs; per-channel notification toggles; observability (metrics, PII-free logs,
OpenAPI + diff, /live vs /ready); dependabot + detekt + release workflow (Play + Docker publish);
LICENSE/CONTRIBUTING/runbook; regenerate README numbers from CI.

**The theme:** the code you have is excellent — the risk is everything *around* the code:
release, versioning, observability, offline, and the few real bugs that screenshot-based testing
structurally cannot catch (frozen animation, offline paths, race conditions, log content).
